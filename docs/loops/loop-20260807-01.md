## 目的 / スコープ

資料パネルのpreviewモードで、PDFとPNG・JPG・JPEG画像の両方を25%〜800%の範囲で拡大縮小できるようにする。通常表示でも最大化表示でもズーム操作を使えるようにし、最大化した画像はパネル本文の利用可能領域全体を使って表示する。

ホワイトボードでは、コードブロックの上下余白と行高を調整して文字切れを防ぐ。Markdown編集時はpreview切替の右側へ太字・斜体・下線・取り消し線・引用・コードブロックのアイコンボタンを配置し、textareaで選択中のテキストへ対応する記法を適用する。適用した書式はpreviewでも視覚的に反映し、既存のlocal draftと30秒cloud自動保存へそのまま接続する。

### 最小の利用者成果

1. PDFのpreviewで通常表示・最大化表示を問わず、25%〜800%の範囲を25%刻みで拡大縮小できる。
2. PDFを2本指でピンチした場合も25%〜800%の範囲へ制限される。
3. 画像のpreviewにも縮小・倍率表示・拡大・100%復帰が表示される。
4. 画像の100%は「表示領域へ収まる倍率」とし、25%はその4分の1、800%はその8倍として扱う。
5. 資料パネルを最大化して画像を選択すると、PDF用サムネイル列の空白を残さず本文領域いっぱいに表示される。
6. コードブロック内の先頭行・最終行が上下で切れず、スクロール時も判読できる。
7. Markdown編集画面で文字列を選択し、6種類のアイコンから書式を適用できる。
8. 書式適用後もtextareaへフォーカスが戻り、対象文字列の選択または編集位置が維持される。
9. 太字、斜体、下線、取り消し線、引用、コードブロックがpreviewへ安全に反映される。
10. 書式操作も通常の文字入力と同様に未保存状態となり、local draftと30秒自動保存の対象になる。

### 対象外

- ブラウザのFullscreen APIを使って資料だけをOS全画面へ表示する機能。
- ズーム倍率をFirestore、IndexedDB、workspace layoutへ永続保存する処理。
- ズーム中心点を固定した高度なpan、慣性スクロール、ダブルクリックズーム、マウスホイールズーム。
- PDFを800%相当の解像度で無制限に再描画する処理。
- GIF、WebP、SVGなど、現在保存対象外の画像形式への対応。
- CommonMarkやGitHub Flavored Markdown全体への準拠、表、リンク、画像、脚注、シンタックスハイライト。
- 色、文字サイズ、箇条書き、番号付きリスト、見出しを適用するtoolbarボタン。
- 書式を共同編集の文字単位差分として同期する処理。

## 前提・現状分析・リスク

### 仕様上の前提

- 依頼の「画面いっぱい」は、既存のパネル最大化中にタイトルバーを除いた資料パネル本文の全面を使う意味とする。ブラウザやOSのFullscreen APIは使わない。
- PDFと画像の最小倍率は25%、最大倍率は800%、初期値とリセット値は100%、ボタン操作は25%刻みとする。
- 通常表示と最大化表示で同じ倍率範囲を使う。最大化解除だけでは倍率をリセットせず、選択資料が変わった時に100%へ戻す。
- 画像の100%は現在の`object-fit: contain`相当の「表示領域へ収める」状態とする。画像の原寸ピクセル数を100%とは定義しない。
- 書式ボタンはMarkdown編集モードで、`preview`切替ボタンの直後に表示する。previewモードでは選択対象のtextareaがないため非表示とする。
- 選択文字が空の場合は書式ボタンをdisabledとし、プレースホルダー文字列は挿入しない。
- 書式記法は次の通りとする。

| 操作           | Markdownへ保存する記法                      | preview要素  |
| -------------- | ------------------------------------------- | ------------ |
| 太字           | `**選択文字**`                              | `strong`     |
| 斜体           | `*選択文字*`                                | `em`         |
| 下線           | `<u>選択文字</u>`                           | `u`          |
| 取り消し線     | `~~選択文字~~`                              | `del`        |
| 引用           | 選択した各行の先頭へ`> `                    | `blockquote` |
| コードブロック | 選択範囲を3連バッククォートのフェンスで囲む | `pre > code` |

### 現行実装との差分

| 領域              | 現行                                    | 計画後                                                     |
| ----------------- | --------------------------------------- | ---------------------------------------------------------- |
| PDFズーム範囲     | 100%〜400%                              | 25%〜800%、100%リセット                                    |
| PDFズーム表示条件 | 資料パネル最大化中だけ                  | previewモードなら通常・最大化の両方                        |
| PDF高倍率描画     | 表示幅×倍率をそのままCanvas解像度へ使用 | 表示倍率は800%まで、backing Canvasは安全な面積・辺長へ制限 |
| 画像ズーム        | なし                                    | PDFと同じ4操作と倍率範囲                                   |
| 最大化画像layout  | PDF用2列gridの影響を受ける可能性がある  | サムネイル列なしの1列で本文全面を使用                      |
| コードブロック    | `pre`へ一括paddingのみ                  | `padding-block`、行高、code表示を明示                      |
| Markdown書式      | textareaへ手入力                        | 選択範囲へ6種類のtoolbar操作を適用                         |
| Markdown preview  | 見出し・リスト・コード・段落・手書き    | インライン4書式と引用を追加                                |
| 保存              | Markdown文字列をlocal/cloud保存         | 同じ保存経路を利用しschema変更なし                         |

### 主なリスクと対策

- PDFを幅800%・高DPIのまま描画すると、Canvasが数億pixelになりメモリ不足やタブクラッシュを起こし得る。CSS上の表示寸法とbacking Canvas解像度を分け、最大辺と最大pixel面積を純粋計算で制限する。
- 高倍率で連続操作するとPDF.jsの古いrender taskが競合する。既存の`renderRequestId`と`cancel()`を維持し、倍率変更のたびに古い描画を破棄する。
- 画像を中央寄せしたまま800%へ拡大すると左上へスクロールできない構造になり得る。拡大対象の内側surfaceをlayout上の実寸として広げ、oversize時は開始位置を左上にする。
- toolbarボタンを押すとtextareaがblurし、ブラウザによって選択範囲が失われる可能性がある。`selectionStart` / `selectionEnd`を操作前に保持し、更新後の`nextTick`でfocusとselectionを復元する。
- 手書きMarkdown parserへ書式を追加すると、`**`と`*`の優先順位や入れ子で誤解析しやすい。長いdelimiterを優先し、pure parserの境界テストを先に固定する。
- `<u>`を扱うために`v-html`を使うとXSS面が悪化する。文字列は必ずVueのtext interpolationで表示し、許可済みのtyped nodeだけを要素へ変換する。
- CSSは既存責務を維持する。PDF固有styleは`textbook-preview.css`、画像固有styleは`ImageMaterialPreview.vue`のscoped style、ホワイトボードpreviewは`whiteboard-panel.css`へ置き、新しいglobal utilityは作らない。

### 依存順

1. Loop 1でDESIGN.mdの既存「100%〜400%・最大化時だけ」を新仕様へ置き換える。
2. Loop 2〜3で共通倍率とPDF描画安全策を先に固定する。
3. Loop 4〜7でPDF・画像のUIと最大化layoutを接続する。
4. Loop 8でコードブロックの可読性を独立して改善する。
5. Loop 9〜13で書式変換とpreview構造をDOMから独立して完成させる。
6. Loop 14〜16でtoolbarとtextarea、自動保存を接続する。
7. Loop 17〜18でレスポンシブ、アクセシビリティ、全回帰を確認する。

## 検証戦略

### ループごとのTDD

- 各Loopは記載した絞り込みVitestを最初に追加・変更し、期待どおりredになることを確認する。
- 最小実装でgreenにした後、責務分離、命名、CSS配置をrefactor checkpointに沿って見直す。
- refactorでコード構造、selector、DOM順を変えた場合は、同じ絞り込みテストを再実行する。
- Canvas、ResizeObserver、PointerEvent、textarea selectionはunit testでmockし、視覚品質と実ブラウザ選択は手動確認へ分ける。

### 手動・ブラウザ確認

1. 通常サイズの資料パネルでPDFを開き、100%から25%まで縮小し、800%まで拡大する。上下限で該当ボタンがdisabledになることを確認する。
2. PDFを800%にしてページ切替と連続ズームを行い、古いCanvasの重なり、長時間のフリーズ、タブクラッシュがないことを確認する。
3. タッチ端末またはDevTools touch emulationでPDFをpinchし、25%〜800%に収まることを確認する。
4. PNG、JPG、JPEGを順に選択し、25%、100%、800%の表示とスクロール範囲を確認する。
5. 画像を選択して資料パネルを最大化し、左側に空のサムネイル列がなく、タイトルバー下から画面下端までpreviewを使うことを確認する。
6. PDFへ戻し、最大化時だけ既存の左サムネイルレールが表示されることを確認する。
7. ホワイトボードへ先頭・末尾に空行を含むコードブロックを入力し、文字が上下で切れないことを確認する。
8. 日本語と英数字を選択し、太字、斜体、下線、取り消し線をそれぞれ適用してpreviewの意味的要素と見た目を確認する。
9. 複数行を選択して引用とコードブロックを適用し、前後本文や改行が失われないことを確認する。
10. 書式適用後に続けて入力し、最後の編集から30秒後に「自動保存済み」へ変わることを確認する。
11. 1680×945、1024×768、390×844、文字倍率200%でズームtoolbarと書式toolbarが欠落・重なりを起こさないことを確認する。
12. Tab、Shift+Tab、Enter/Spaceだけで全アイコンを操作し、Tooltip、`aria-label`、focus ringを確認する。

## ロールバック・フォローアップ

- Firestore document、Storage path、security rules、既存Markdown保存schemaは変更しないためdata migrationは不要。
- PDF高倍率描画で端末差が大きい場合、25〜800%のUI契約は維持したままCanvas最大pixel面積だけを調整できる構造にする。
- 800%のPDFが低解像度に見える端末では、端末メモリを推測して無制限化せず、段階的なtile描画を別計画で検討する。
- 画像zoomで中心位置を維持する要望が出た場合、scroll offset補正を別Loopとして追加する。
- Markdown parserを今後、表・リンク・数式・syntax highlightまで広げる場合は、保守中のMarkdown library導入とsanitize方針を別計画で比較する。
- toolbarの書式解除や複雑な入れ子で期待差が出た場合、純粋関数testへ再現ケースを追加してからdelimiter規則を拡張する。
- 狭幅で6アイコンが2段になって編集領域を圧迫する場合、アクセシブルなoverflow menu化をフォローアップ候補とする。
