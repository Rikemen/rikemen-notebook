## 目的・スコープ

### 目的

- PDFを選択した直後に、選択した実ファイルのページをプレビューとサムネイルへ表示する。
- `src/features/textbook/materials.ts` の `sampleMaterials` を本番初期値から除去し、未登録時は空状態を表示する。
- ログインユーザーのPDF本体をFirebase Storage、metadataをFirestoreへノート単位で保存し、再読込後も復元する。
- 未ログインユーザーは現在の説明どおり、上限内のPDFをブラウザセッション中だけ閲覧できるようにする。
- 読込、解析、保存の失敗をUIへ表示し、成功していない資料を「保存済み」と誤表示しない。

### 最小の有用な完了状態

1. ダミー3件が表示されない。
2. 有効なPDFを選ぶと、固定文章ではなく実際の1ページ目が表示される。
3. ページ選択で実PDFの該当ページへ切り替わる。
4. ログイン中に保存した教材だけが、同じノートを再表示したときに復元される。
5. 別ユーザー・別ノートの教材は混ざらない。

### 非対象

- OCR、本文検索、PDFからの目次自動抽出。
- PDF編集、注釈、回転、ページ削除、結合。
- ホワイトボードへのページ貼り付け。
- 教材共有、公開URL、管理者閲覧。
- 5GB級PDFを常に快適に描画できると保証する性能最適化。大容量時の安全な失敗表示までは対象とする。
- 既存データがある場合の一括移行処理。必要性を確認後、別計画へ分ける。

## 前提・現状分析・リスク

### 現状と直接原因

| 箇所 | 現状 | 問題 |
| --- | --- | --- |
| `src/components/textbook/TextbookPanel.vue` | `File`から表示用metadataだけを作り、`select-file`をemitする。 | 親の`WorkspaceView.vue`はイベントを購読しておらず、実ファイルは保持・保存されない。 |
| `src/components/textbook/TextbookPreview.vue` | 固定の「関数の極限」、数式、CSSグラフを表示する。 | 選択したPDFを読んでも描画していない。 |
| `src/components/textbook/PageThumbnailStrip.vue` | CSS製の白紙サムネイルを6個表示する。 | 実ページ画像ではなく、ページ数も固定値に依存する。 |
| `src/features/textbook/materials.ts` | `sampleMaterials` 3件と `pageCount: 6` を定義する。 | 未アップロード教材が全ノートへ初期注入される。 |
| `src/features/textbook/textbookPanelStore.ts` | 初期教材配列を受け取り、Piniaメモリ内だけへ追加する。 | 再読込で消え、ダミーと実教材の境界も曖昧になる。 |
| `src/features/textbook/textbookRepository.ts` | 保存先計算とInMemory実装だけがある。 | Firebase Storage/Firestoreへの実保存・取得がない。 |
| `src/utils/firebase.ts` | Auth、Firestore、Functionsだけを初期化する。 | Storage clientとStorage emulator接続がない。 |
| `package.json` | PDFレンダリング依存がない。 | ブラウザ内でPDFページをCanvasへ描画する実装が存在しない。 |

現在の関連テストは `9 files / 32 tests` が成功しているが、「ファイル名が一覧へ追加された」ことだけを成功条件にしているため、実PDFが表示・保存されない状態を検出できていない。

### 実装方針

- PDF描画は `pdfjs-dist` を使用し、Viteのworker設定を専用アダプターへ閉じ込める。
- ローカル選択直後は `URL.createObjectURL(file)` をPDF.jsへ渡し、ファイル全体を手動でArrayBuffer化してPiniaへ保持しない。
- 永続metadataとセッション限定source URLを別の型・stateで管理する。blob URLはFirestoreへ保存しない。
- ログイン時はローカルblobで即時プレビューしながら、Storage uploadとFirestore metadata保存を進める。
- 保存済みPDFはmetadataの`storagePath`から実行時にdownload URLを解決する。期限付きURLをSSoTとして保存しない。
- PDF documentは選択資料ごとに1回読み込み、メインページとサムネイルで共有する。画面外サムネイルは遅延描画する。
- `DESIGN.md` 8.1の「3モード」「実ページ比率」「選択同期」を維持する。

### 前提

- 現行UIはFirebaseへ実保存していないため、`sampleMaterials` 削除だけで本番ユーザーデータは失われない想定とする。
- 教材は `uid + noteId + materialId` で分離する。既存の `/users/{uid}/textbooks/{textbookId}` を利用中の外部処理がある場合は、実装前に移行または互換読込を決める。
- `ファイルを選択` ボタンは現状無反応なので、履歴選択ダイアログの仕様が定まるまでは同じhidden file inputを開く副導線として扱う。
- `accept="application/pdf"` は選択UIのヒントにすぎないため、実装側でもMIME、サイズ、0 byteを検証する。

### 主なリスク

- PDF.js worker URLの設定を誤ると開発環境では動いてもproduction buildで失敗する。unit testに加え`npm run build`とproduction previewで確認する。
- 5GBの許容上限はブラウザプレビュー能力と一致しない。全ページ同時描画を避け、読込不能時は保存処理と区別したエラーを出す。
- Storage成功後にFirestore保存が失敗すると孤児ファイルが残る。repositoryでStorage削除を補償処理として行う。
- component unmount、資料切替、ページ連打で古いrender taskが完了すると別ページを上書きし得る。render cancelとrequest tokenで防ぐ。
- blob URLを早くrevokeすると再マウント時に表示不能になり、解放しないとメモリを保持する。資料削除・state破棄時だけ明示解放する。
- PDF.jsで暗号化、破損、巨大PDFを読む際の例外種別は一定でない。技術例外をそのままユーザーへ出さず、再選択可能な状態へ戻す。
- note-scoped pathを追加する場合、Firestore rules、Storage rules、path helper、repositoryを同じ変更単位で整合させる。

## 検証戦略

### ループごとの自動検証

- 各Loopは記載した絞り込みVitestを、実装前のredと実装後のgreenで実行する。
- refactor後に型、依存、DOM構造を触った場合は同じ絞り込みtestを再実行する。
- PDF.js、Firebase SDK、Canvas、IntersectionObserverはunit testではport/mockを使い、ネットワークと実ブラウザ依存を避ける。
- 最後に実PDF fixtureを使うintegration testを少数だけ置き、mockと実アダプターの乖離を検出する。

### 必須シナリオ

| シナリオ | 期待結果 |
| --- | --- |
| 新規ノートを開く | ダミー0件、PDF追加案内、目次・プレビューは無効 |
| 2ページPDFを選択 | 実page countが2、1ページ目の実内容をCanvas表示 |
| 2ページ目を選択 | メインCanvasとthumbnail選択が2ページ目で同期 |
| PDF以外・0 byte・上限超過 | 一覧へ追加せず日本語エラー表示 |
| 壊れた・暗号化PDF | ダミーfallbackせず再選択可能 |
| ログインupload成功 | StorageとFirestoreへ保存し、保存済み表示 |
| Firestore保存失敗 | 保存失敗表示、先に保存したStorage objectを補償削除 |
| 同じノートを再読込 | 保存済み実教材を復元しプレビュー可能 |
| 別ノート・別ユーザー | 教材が表示されず、rulesでもreadを拒否 |
| 未ログインupload | Firebase未呼出、同一session内だけ利用可能 |
| ページ連打・パネルclose | 古い描画が上書きせず、例外やconsole errorがない |

## ロールバック・フォローアップ

- PDF.js描画でproduction固有問題が出た場合、ダミーへ戻さず「一覧・保存は維持し、プレビューを明示的エラー状態にする」feature flagを用意する。
- Firebase schema変更は旧 `/users/{uid}/textbooks/{textbookId}` rule/pathを同時削除しない。実データがないことを確認後、別commitで廃止する。
- 新規保存を止める必要がある場合はUIのupload導線を無効化し、既存readは維持する。保存済みデータを自動削除しない。
- 実装commitは少なくとも「ダミー除去」「PDF描画」「Firebase保存・rules」「統合/UI」の論理単位へ分ける。
- 後続候補は、教材削除、OCR/検索、目次自動生成、ホワイトボード貼付、大容量PDF性能測定とする。
