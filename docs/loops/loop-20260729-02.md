## Goal / Scope

資料パネル、ホワイトボードの手書きイラスト操作、各パネル最大化時の作業領域を、現在のワークスペース構造を維持したまま改善する。

- ユーザー向け表示名を「教科書」から「資料」へ変更する。
- 資料パネル上部に次の3モードを切り替えるアイコンボタンを配置する。
  - 資料一覧
  - 目次
  - プレビュー
- 各モードの本文には、そのモードに必要な内容だけを表示する。
- 資料一覧には現在のノートに追加された資料だけを表示する。
- PDFアップロードとファイル選択は資料一覧モードだけに表示する。
- 目次は資料単位で管理し、ユーザーがタイトルとページ番号を追加できるようにする。
- 目次項目を選択するとプレビューモードへ移動し、指定ページを選択する。
- ホワイトボードの手書き追加ボタンを文字ではなく鉛筆アイコンにする。
- 保存済みイラストを選択すると、編集・削除を選べるダイアログを表示する。
- プレビュー画像直下にある既存の「編集」ボタンを削除する。
- イラスト削除時は、画像データとMarkdown内の参照を同時に削除する。
- 各パネルを最大化したときは、パネル本文をviewport下端まで広げる。
- ホワイトボードのMarkdown入力・プレビュー、コード入力、図表Canvas、AIチャット履歴、資料の各モード本文が、操作列を除く残りの高さを使用する。
- 最大化中もページ全体をスクロールさせず、必要なパネル本文だけをスクロール可能にする。
- デザインは `DESIGN.md` をSSoTとし、既存のモノクロ、青・赤アクセント、ニューモーフィズムを維持する。

今回の非対象:

- PDF本文の解析やPDFから目次を自動抽出する処理。
- PDF.jsなどを使った実PDFレンダリングへの全面移行。
- 目次項目のドラッグ並び替え。
- 目次項目の多段階編集・削除・親子移動。初回は追加と選択を必須範囲とする。
- Firestore/Storageの保存形式変更や既存教材データの移行。
- ブラウザ再起動後まで資料モード・目次・手書き内容を永続化する新規repository設計。

## Assumptions and Risks

- 表示名は「資料」へ変更するが、`WorkspacePanelId` の `textbook`、`src/components/textbook/`、`src/features/textbook/`、既存Firestore/Storageの `textbooks` パスは維持する。内部IDまで変更すると、保存済みレイアウトや将来のデータ移行へ影響するためである。
- `localStorage` に保存済みのパネルレイアウトには旧タイトル「教科書」が含まれる可能性がある。レイアウト全体をリセットせず、`sanitizePanelLayout()` でIDに対応する最新タイトル「資料」へ補正する。
- 資料パネルの初期モードは「資料一覧」とする。
- 「目次をタップするとプレビュー表示のとき、そのページにジャンプする」は、目次選択時にプレビューモードへ自動切替し、そのページを選択する仕様として扱う。
- 目次は `noteId + materialId` 単位で管理する。同じ資料名でも別ノートの目次とは共有しない。
- 目次項目は `id`、`title`、`page`、`children` を持つツリーモデルとする。今回の追加フォームはルート項目を追加し、ネスト表示に対応できるデータ構造だけを先に用意する。
- ページ番号は1以上の整数を必須とする。総ページ数が取得できる場合は上限も検証し、現在のモックでは既知のページ数を使用する。
- 現在の資料一覧は `TextbookPanel.vue` 内のfixtureであり、実ファイル保存は `select-file` emitまでである。今回のノート別資料登録はPinia内の表示用metadataを対象とし、既存のアップロード上限判定と外部保存イベントは維持する。
- 未ログイン10MB、ログイン済み5GBの上限と保存可否は既存 `accessPolicy.ts` をSSoTとして変更しない。
- 資料・目次・選択状態は、パネルOFF/ONや同一Piniaでの再マウント後に保持する。ブラウザ再起動後の永続化は別計画でrepository境界を設計する。
- 手書きイラストは1つのMarkdown参照から表示される前提だが、削除処理は同じdrawing IDへの参照が複数ページに存在しても壊れた参照を残さないよう、ノート内の全ページを対象にする。
- イラスト操作ダイアログは画像クリックで開き、背景クリック、閉じるボタン、`Esc`で閉じられるようにする。削除は赤アクセントを使い、編集は青の主要操作とする。
- `WhiteboardPanel.vue` は既に大きいため、ダイアログUIと資料モード切替UIは専用コンポーネントへ分離する。
- CSSは資料関連を各Vueコンポーネントのscoped style、既存ホワイトボード本体を `src/styles/components/whiteboard-panel.css`、新規ダイアログを専用コンポーネントのscoped styleへ置く。
- 最大化パネルの外枠は既にviewport全体へ広がる。余白が残る主因は、子要素へ高さが伝播していないことと、ホワイトボードの470px、コード・Canvasの260px、AI履歴の250pxという固定制約である。
- 最大化専用の固定px値を増やさず、`height: 100%`、`min-height: 0`、`grid-template-rows: auto minmax(0, 1fr) auto`を基本に、親から子へ利用可能高を渡す。
- 最大化中の `MovablePanel` はpanel bodyをスクロールさせず、ホワイトボード本文、コードtextarea、チャット履歴、資料本文など最も内側の実コンテンツ領域だけをスクロールさせる。
- 通常のドッキング表示と自由配置表示も同じ高さ契約を使い、最大化専用のDOM複製やviewport基準のabsolute配置は追加しない。
- CanvasはCSSだけで引き伸ばすと描画がぼやけるため、表示サイズに合わせてbacking bufferを更新して再描画する。`ResizeObserver`が利用できないテスト環境では安全にスキップできる境界を持たせる。
- 最大化中も各パネル自身のタイトルバーと復元ボタンは固定表示し、入力欄や履歴のスクロールに巻き込まない。

## Verification Strategy

- 各Loopは必ず `失敗テスト追加 -> 最小実装 -> 対象テスト成功 -> リファクタリング -> 対象テスト再実行` の順で進める。
- パネル表示名と保存済みレイアウト補正は `workspacePanels.test.ts` と `panelLayout.test.ts` で確認する。
- 資料モード、資料一覧、目次、ページ遷移は `textbookPanelStore.test.ts` のstateテストと各componentテストへ分ける。
- 目次のvalidationとtree更新は `materialTableOfContents.test.ts` でDOMなしに確認する。
- イラスト配列とMarkdown参照の削除は `whiteboardDrawings.test.ts` で純粋関数として確認する。
- ダイアログ表示、編集、削除の結合は `WhiteboardPanel.test.ts` で確認する。
- 最大化外枠から本文への高さ伝播は `MovablePanel.test.ts` とパネル別componentテストへ分ける。
- Canvasのサイズ計算は純粋関数、ResizeObserverとの接続はcomponentテストで確認する。
- レスポンシブはunit testだけで完了扱いにせず、実ブラウザのviewportと `documentElement.scrollWidth === clientWidth` で確認する。
- 実ブラウザでは各最大化パネルについて、作業領域の `getBoundingClientRect().bottom` がpanel bodyの下端から16px以内であることを確認する。

| 保存済み画像 | 画像を選択 | 編集・削除ダイアログを表示 |
| 操作ダイアログ | 編集する | 対象strokesを手書き画面へ復元 |
| 再編集後 | 保存 | 同じdrawing IDの画像を更新 |
| 操作ダイアログ | 削除する | 画像、drawing、Markdown参照を削除 |
| 複数画像あり | 1件削除 | 他の画像と本文を維持 |

## Rollback / Follow-up Notes

- 表示名変更を戻す場合も内部ID `textbook` は変更しないため、`workspacePanels` とcanonical titleの差し戻しだけで対応できる。
- 目次または資料モードに問題がある場合、3モードUIをfeature flag化せず、資料一覧を初期modeとして固定して該当componentだけを切り戻す。
- イラストダイアログに問題がある場合、drawingデータモデルは維持したまま画像クリックを一時的に無効化できる。削除済みデータの自動復元は行わない。
- ブラウザ再起動後の資料・目次・手書き内容保存が必要になった時は、次の別計画で扱う。
  - `users/{uid}/notes/{noteId}/materials/{materialId}` のFirestore metadata
  - `users/{uid}/notes/{noteId}/materials/{materialId}/tocEntries/{entryId}` の目次
  - Storage上のPDFと手書き画像
  - Firestore Security Rules、Storage Rules、既存 `textbooks` パスからの移行
- PDFの実ページ数取得と実プレビューは、PDF.js導入、worker設定、ページキャッシュ、サムネイル生成を含むため別ループ計画に分ける。
- 最大化全高表示を切り戻す場合は、親の高さ契約を残してパネル別の可変行だけを戻す。`MovablePanel`や`WorkspaceView`へ固定viewport計算を再導入しない。
