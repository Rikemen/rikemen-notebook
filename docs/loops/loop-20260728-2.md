## Goal / Scope

`docs/loops/asssets/mock.png` と `DESIGN.md` を基準に、現在のMVPを「数学まとめノート」として使える作業画面へ近づける。

- 今後のUI実装では `DESIGN.md` をSingle Source of Truthとして扱うルールを追加する。
- 新規登録とログインを別画面に分ける。ただし認証処理は既存のGoogle認証サービスを共通利用する。
- HOMEは未ログイン時にアプリの使い方だけを表示し、ログイン済みならノート一覧と検索を表示する。
- ノート画面は添付モックを参考に、左に教科書、中央にホワイトボード、右上にAIチャット、右下に図表Canvasとコードを配置する。
- 各パネルは移動、リサイズ、最大化、最小化、別タブ表示に対応する。
- 図表生成エリアはp5.webeditorのように、`sketch.js` を入口にしつつ複数ファイル、class、関数分割を扱えるコード編集モデルにする。
- AIチャットは一旦固定応答でよいが、OpenAI API利用を前提に安全なadapter境界を置く。
- 数式はKaTeXまたはMathJaxを利用し、ホワイトボードとAIチャットで文字化けしない表示を保証する。

今回の非対象:

- 本番のOpenAI API呼び出し実装。
- PDF本文解析、OCR、ページ画像生成の本格実装。
- p5.jsコードをサーバー側で安全に実行する仕組み。
- 共同編集、共有URL、権限移譲。
- Playwrightなど未導入のE2E基盤を必須依存として追加すること。必要なら別ループで導入判断する。

## Assumptions and Risks

- 現在の実装には `NotesListView.vue`, `WorkspaceView.vue`, `TextbookPanel.vue`, `AiChatPanel.vue`, `DiagramCodePanel.vue` などのMVP骨格があるため、広い作り直しではなく段階的に差し替える。
- `DESIGN.md` はモノクロ基調、青を主要操作、赤を危険/エラー、ニューモーフィズム、Radius 8-22px、パネル操作順序、レスポンシブ方針を定義している。実装時はこの文書をUI判断の基準にする。
- `DESIGN.md` のルール化は `.agent/rules/design-system-source-of-truth.md` の追加を想定する。必要なら `AGENTS.md` の参照先は既存どおり `.agent/rules/` のままで足りる。
- p5.js実行はブラウザ内実行になるため、信頼できないコードの安全性に注意する。MVPではローカルユーザーが自分で書いたコードを実行する前提に留める。
- OpenAI APIキーはクライアントに置かない。将来は Firebase Functions 経由で `uid + date` のAI利用上限と合わせて実行する。
- 数式レンダリングライブラリの導入時は、バンドルサイズとCSS読み込みを確認する。KaTeXを優先候補、複雑なMathML/アクセシビリティが必要ならMathJaxを検討する。
- パネル移動/リサイズはDOMイベントが絡むため、純粋関数のレイアウト計算を先にテストし、コンポーネントテストは最小限のイベント確認に留める。
- 既存CSSはTailwind中心だが、今回のデザインはトークンが重要なため、`src/styles/` 配下の責務別CSS追加を計画する。グローバルCSSを無秩序に増やさない。

## Verification Strategy

- 各ループ直後は表に記載した対象テストを実行する。
- UI/CSS変更のあるループでは、該当コンポーネントテストに加えて `npm run build` を節目で実行する。
- 依存追加が必要なループでは、導入前に `package.json` と既存代替を確認し、導入後に `npm run test` と `npm run build` を実行する。
- 数式ライブラリ導入後は、少なくとも `x^2`, `\int_0^1 x^2 dx`, 行列、分数、添字を確認する。
- p5.js導入後は、canvasが空でないこと、再実行時に古いp5インスタンスが残らないことを確認する。
- パネル操作は、純粋関数で位置/サイズ/状態をテストし、DOMイベントテストは最小限に留める。
- レスポンシブは `responsiveWorkspace` のユニットテストで操作可否を固定し、実装後にブラウザで Desktop/Tablet/Mobile を目視確認する。
- 完了時にまとめて実行するコマンド:

```bash
npm run test
npm run build
```

## Rollback / Follow-up Notes

- デザイン崩れが大きい場合は、まず `src/styles/base/tokens.css` と共通UIプリミティブだけ残し、画面単位のCSSを戻せるようにする。
- パネル移動/リサイズが複雑化した場合は、自前実装を中断し、`interact.js` などの導入を別計画で評価する。
- p5.js実行はセキュリティ面の確認が必要なため、共有ノートや他人コード実行の前にsandbox方針を別途設計する。
- OpenAI API連携は固定応答adapterが安定してから、Firebase Functions側のquota enforcementと合わせて別ループにする。
- KaTeX/MathJaxのどちらを採用するかは、表示品質、アクセシビリティ、バンドルサイズを見て決める。採用後はレンダラーコンポーネントに依存を閉じ込める。
