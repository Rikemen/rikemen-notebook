## Goal / Scope

このループでは、アプリ名を **Gauss Notebook** として扱うためのブランド変更、ブラウザタブ名とfavicon、共通ヘッダー、言語切替の一時削除、Google認証後の遷移先変更を行う。

- ヘッダーは `DESIGN.md` に従い、白背景、軽い影、モノクロ基調、青を主要操作に限定した見た目にする。
- 文字ロゴは「Gauss Notebook」とする。
- ブラウザタブの `<title>` は「Gauss Notebook」にする。
- faviconは添付画像として配置済みの `public/favicon.png` を参照する。domainやURL構造は現時点では変更しない。
- アプリ名が今後ぶれないよう、ruleに「このアプリの名称はGauss Notebook」と追記する。
- 言語切り替えUIは一旦不要とし、日本語のみの利用に絞る。
- Google新規登録/ログイン成功後は `/notes` ではなくHOME `/` に遷移する。
- ノート詳細ページは通常表示をCSS Gridのドッキングレイアウトとし、自由配置モードとはCSS/座標を分離する。
- デスクトップは左25%/中央50%/右25%相当、右カラム上下2段、1280px以上3カラム、768〜1279pxは2カラム、767px以下は縦積みとする。

今回の非対象:

- ドメイン変更、OGP画像、PWA manifest、アプリストア用アイコン生成。
- 英語UIの削除やi18n基盤そのものの撤去。今回はUI上の言語切替を外すだけに留める。
- Firebase AuthenticationのProvider設定変更。
- ロゴ画像の新規生成。今回は文字ロゴを使う。

## Assumptions and Risks

- 現在の `index.html` は `<title>firebase-vue3-startup-kit</title>` かつ `/favicon.ico` を参照しているため、`public/favicon.png` へ参照を変える必要がある。
- `src/components/Layout.vue` は旧テンプレート由来の青いヘッダーと `Firebase Vue3 kit` 表示、`Languages` コンポーネントを持つ。ここを共通ヘッダーとして更新する。
- `WorkspaceHeader.vue`, `HomeUsageGuide.vue`, `SignUp.vue`, `PanelPopoutView.vue` などに「数学まとめノート」の表示が残っているため、ブランド定数で置換する。
- `useGoogleAuthAction.ts` は認証成功後に `/notes` へ遷移している。HOME遷移へ変更すると、既存の `SignUpPage.test.ts` と `LoginPage.test.ts` の期待値更新が必要になる。
- 言語切替UIを外しても、既存の `/:lang` ルートやi18n utilityをすぐ撤去すると影響が広い可能性がある。初回は画面から非表示にすることを優先し、ルート整理は別ループで判断する。
- ヘッダーの白背景化は既存Tailwind classと新しいCSSトークンが混在するため、`src/styles/base/tokens.css` とコンポーネントscoped CSSの責務を確認する。
- 現在のノート詳細は、通常表示でも `MovablePanel.vue` が `position:absolute` と `transform: translate(...)` を使い、`WorkspaceView.vue` のデスクトップ領域にGridが適用されない。これが重なり、画面外はみ出し、横スクロール、内部コンテンツ切れの主因と推定する。
- 既存または今後のlocalStorage保存値に古い座標が残ると、修正後も画面外配置が復元される可能性があるため、レイアウトバージョンと保存値検証が必要になる。

- Refactoring checkpoint: ヘッダーや操作ボタンをスクロール領域へ入れない。
- Completion criteria: パネルタイトルと操作ボタンが常に表示される。

### Loop 17: 子要素の押し広げ防止

- Objective: 教科書、ホワイトボード、AI、図表コードの内部コンテンツが親パネルを押し広げないようにする。
- TDD test to add or change: `tests/workspace/workspaceDockedLayout.test.ts` に通常ドッキング構造を保つ確認を追加する。
- Minimal implementation steps:
  - `MovablePanel.vue` のbody配下へ `box-sizing:border-box; min-width:0` を適用する。
  - `TextbookPanel.vue`, `TextbookList.vue`, `TextbookPreview.vue`, `WhiteboardPanel.vue`, `DiagramCodePanel.vue`, `CodeEditorPanel.vue`, `P5CanvasPreview.vue` に `min-width:0` と親幅内の制約を追加する。
  - 長いPDF名はellipsisまたはwrapで処理する。
- Unit test command to run after the task: `npm run test -- workspaceDockedLayout TextbookPanel WhiteboardPanel DiagramCodePanel`
- Refactoring checkpoint: 右へずれる原因を固定marginや大きなmin-widthで隠さない。
- Completion criteria: パネル幅より内部コンテンツが大きくならない。

### Loop 18: 自由配置座標clamp

- Objective: 自由配置モードの移動・リサイズをworkspace左上原点で親領域内に収める。
- TDD test to add or change: `tests/workspace/panelLayout.test.ts` と `tests/components/MovablePanel.test.ts` を更新し、docked時はdragなし、free時だけmove/resize emitを確認する。
- Minimal implementation steps:
  - `WorkspaceView.vue` で panel-grid の `clientWidth/clientHeight` を `stageBounds` として保持する。
  - `moveLayoutPanel` と `resizeLayoutPanel` に実測boundsを渡す。
  - `resize` イベント時に保存済み座標を再clampする。
- Unit test command to run after the task: `npm run test -- panelLayout MovablePanel`
- Refactoring checkpoint: 座標計算は `panelLayout.ts` の純粋関数に閉じる。
- Completion criteria: 移動・リサイズ後もパネルが親領域外へ出ない。

### Loop 19: 保存レイアウト検証

- Objective: localStorage等に保存された古い/不正な座標をリセットする。
- TDD test to add or change: `tests/workspace/localWorkspaceLayoutStorage.test.ts` を追加し、現行versionだけ復元し、古いversion/破損JSONは破棄することを確認する。
- Minimal implementation steps:
  - `WORKSPACE_LAYOUT_VERSION` を定義する。
  - 保存形式を `{ version, panels }` にする。
  - `NaN`, 負数, 画面外, 過大サイズ, 欠損panelは `createDefaultPanelLayout(noteId)` へ戻す。
- Unit test command to run after the task: `npm run test -- localWorkspaceLayoutStorage panelLayout`
- Refactoring checkpoint: Firestore保存境界とlocalStorage境界を混ぜない。
- Completion criteria: 古い保存座標でレイアウト崩れが再発しない。

### Loop 20: レスポンシブ固定

- Objective: 1280px以上3カラム、768〜1279pxは2カラム、767px以下は縦積みへ切り替える。
- TDD test to add or change: `tests/workspace/responsiveWorkspace.test.ts` と `workspaceDockedLayout` を維持する。
- Minimal implementation steps:
  - docked gridを `minmax(280px, 0.9fr) minmax(500px, 2fr) minmax(320px, 1fr)` にする。
  - `@media (width < 1280px)` で2カラム、`@media (width < 768px)` で1カラムへ切り替える。
  - 各breakpointで `minmax(0, 1fr)` を使い、横スクロールを出さない。
- Unit test command to run after the task: `npm run test -- responsiveWorkspace workspaceDockedLayout`
- Refactoring checkpoint: breakpointごとのCSSを同じコンポーネントの責務内にまとめる。
- Completion criteria: 1680×945、1440×900、1280×720の想定幅でパネルが重ならず、横スクロールを発生させない構造になる。

## Verification Strategy

- 各ループでは表に記載した対象テストを実行する。
- メタ情報変更後は `index.html` を直接検証する単体テストを通す。
- ヘッダー変更後は `LayoutHeader`, `HeaderMenu`, `brandCopy` の順に確認する。
- 認証遷移変更後は `SignUpPage`, `LoginPage`, `HomePage` をまとめて確認する。
- 完了時に以下を実行する。

```bash
npm run test
npm run build
```

- ローカル目視確認では、`/`, `/signup`, `/login`, `/notes/:noteId` を開き、白いヘッダー、`Gauss Notebook` 表記、言語切替非表示、favicon表示、ログイン後HOME遷移を確認する。

## Rollback / Follow-up Notes

- ブランド名変更で表示崩れが出た場合は、まず `src/config/appBrand.ts` と `Layout.vue` の表示だけ戻せるようにする。
