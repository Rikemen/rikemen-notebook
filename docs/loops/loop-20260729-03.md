## Goal / Scope

ワークスペースのパネル配置、AIチャット履歴、Firebase Functions経由のOpenAI応答、スケッチ実行環境を、既存のノート単位ワークスペースへ段階的に追加する。

- 自由配置モードでは、通常状態のパネル右下からサイズを変更できることを明確にする。
- 移動・リサイズ後のパネルをワークスペース内へclampし、最小サイズを守る。
- ドッキング表示で表示中パネルが2枚の場合、768px以上では左右50%ずつに配置する。
- AIチャット上部に「新規チャット」と「履歴」のアイコン操作を置く。
- AIチャットをユーザー・ノート・スレッド単位で分離し、Firestoreへ履歴保存する。
- 履歴から30ターン未満の会話を選択し、続きから送信できるようにする。
- 1ターンを「ユーザーの1送信と、それに対するAIの1応答」と定義し、1スレッド30ターンを上限にする。
- 30ターン到達後は会話を要約し、その要約を文脈として持つ新規スレッドへ引き継げるようにする。
- OpenAI APIはブラウザから直接呼ばず、`sendMathChatMessage` Callable Functionだけから呼び出す。
- OpenAI APIキーはFirebase Secret Managerで管理し、キーが必要な確認段階でユーザーへ安全な設定方法を案内する。
- ログイン、ノート所有権、1日100回上限、1スレッド30ターン上限をFunctions側でも再検証する。
- 「図表・コード」パネルのユーザー向け名称を「スケッチ」へ変更する。
- スケッチプロジェクトを `index.html`、`style.css`、`sketch.js` から開始する。
- `index.html` はp5.js 2.3.0をjsDelivr CDNから読み込み、`sketch.js`をscriptタグで読み込む。
- ユーザーがJavaScriptファイルを追加し、`index.html`へscriptタグを記述して実行順を管理できるようにする。
- コードは親画面から隔離したsandbox付きiframeで実行する。
- index.htmlで読み込んでいるp5.jsのバージョンを、スケッチパネル上部にタグとして表示する。
- デザインは `DESIGN.md` をSSoTとし、既存のモノクロ、青・赤アクセント、ニューモーフィズムを維持する。

今回の非対象:

- AI応答のストリーミング、添付ファイル、音声、画像入力。
- OpenAIモデルの自動切り替え、複数プロバイダー対応、プロンプト管理画面。
- チャットスレッドの名称手動編集、削除、検索、共有。
- 複数端末間のリアルタイム同期。初回表示と操作後のFirestore保存を対象とする。
- p5.js以外のnpm package管理、ビルドツール、TypeScript transpile。
- Monaco Editorなどの高機能コードエディタ、lint補完、デバッガ。
- スケッチファイルのフォルダ階層、名前変更、削除、ドラッグ並び替え。
- スケッチプロジェクトのFirestore保存。今回も既存どおり同一Piniaセッション内で保持する。
- ユーザーコードから任意の外部API、親画面、Firebase Authentication、localStorageへアクセスする機能。

## Assumptions and Risks

- `WorkspacePanelId` の `diagram-code`、既存ディレクトリ名、保存済みレイアウトキーは維持する。表示名だけを「スケッチ」へ変更する。
- `sanitizePanelLayout()` で保存済みタイトル「図表・コード」をcanonical title「スケッチ」へ補正し、レイアウト全体はリセットしない。
- 自由配置での移動・リサイズは既存方針どおり1280px以上で有効とする。767px以下では自由配置とリサイズを有効化しない。
- リサイズハンドルは右下に32px前後の操作領域を持たせ、見える斜線自体は小さく保つ。パネル内容を過度に覆わない。
- ドッキングの「2枚」は、`normal`または`maximized`ではなく、通常表示中の `normal` パネルが2枚の状態を指す。最大化中は既存の1パネル全画面表示を優先する。
- 2パネルの順序は `workspacePanels` の定義順を使う。768px以上は2列、767px以下は1列の縦積みとする。
- AI履歴は `users/{uid}/notes/{noteId}/chatThreads/{threadId}` と、その配下の `messages/{messageId}` に保存する。
- AI履歴の取得・保存はログイン済みユーザーだけに許可し、`uid` を引数としてrepositoryへ渡す。匿名ユーザーには既存どおりAI入力を許可しない。
- Firestore Rulesの既存 `users/{userId}/notes/{noteId}/{document=**}` は本人パスだけを許可している。新パスの所有者分離テストを追加し、必要な場合だけ明示的なmatchへ分割する。
- 新しい履歴モデル導入前のクライアント内メッセージは永続データではないため、Firestore移行処理は行わない。
- スレッドタイトルは最初のユーザー発言を一定文字数で切り詰めて自動生成する。空スレッドは「新しいチャット」と表示する。
- 30ターン到達後も元スレッドは履歴として閲覧できる。同じスレッドへの入力は無効化し、「要約して新しいチャットへ」を表示する。
- 要約は自動実行せず、ユーザーが引き継ぎ操作を押したときに実行する。これにより30ターン目のAI応答を確認してから移動できる。
- 要約API呼び出しもAPI利用料が発生するため、日次100回上限の1回として数える。上限到達中は要約できず、元スレッドを保持して再試行可能にする。
- 後続スレッドは `sourceThreadId` と `inheritedSummary` を持ち、最初のAI送信時に要約を文脈としてclientへ渡す。
- 現在の固定応答clientにも要約用の決定的なfake実装を追加し、unit testでは維持する。本番UIはLoop 38でFunctions clientへ切り替える。
- Firestore保存失敗時は画面上の履歴を成功扱いにせず、storeでエラーを保持して再試行可能にする。
- OpenAI APIキー名は `OPENAI_API_KEY` とし、Vueの `.env`、`VITE_*`、`src/`、Firestore、ログへ保存しない。
- 本番キーはFirebase Secret Managerへ保存し、Callable Functionへ `defineSecret()` と `secrets` optionで明示的にbindする。
- Local Emulatorでは `functions/.secret.local` を利用する。作成前に同ファイルを `functions/.gitignore` へ追加する。
- 実装エージェントはキーを必要とする実通信確認の直前に設定方法をユーザーへ案内し、キー本文をチャットへ貼り付けるよう求めない。モックを使うunit testとbuildはキーなしで先に進める。
- OpenAI SDKは `functions/package.json` のみに追加し、サーバー側でResponses APIを呼ぶ。採用モデルは `OPENAI_MODEL` の非秘密設定へ分離し、実装時点の公式ドキュメントと利用可能モデルを確認して初期値を決める。
- Callable payloadから送られた `uid` は信用しない。所有者は必ず `request.auth.uid` から取得し、payload自体から `uid` を削除する。
- 通常応答と要約の双方で、Functionsが `users/{uid}/notes/{noteId}` の存在を確認してからOpenAIを呼ぶ。
- サーバー側の日次利用数は `users/{uid}/aiUsage/{YYYY-MM-DD}` に保存する。このpathはクライアントからread/writeを許可せず、Admin SDKだけが更新する。
- quotaはOpenAI呼び出し前にFirestore transactionで予約し、同時送信でも100回を超えないようにする。予約後のAPI失敗は利用試行として1回に数え、再試行による意図しない無制限利用を防ぐ。
- prompt、履歴件数、会話全体の文字数、出力token数に上限を設け、過大リクエストをOpenAIへ送らない。
- OpenAIやSecretの内部エラーはFunctionsログへ構造化記録するが、APIキー、全文prompt、会話本文は記録しない。クライアントには安定した日本語エラーだけを返す。
- p5.jsの初期バージョンはユーザー指定どおり `2.3.0` とし、既定CDNは `https://cdn.jsdelivr.net/npm/p5@2.3.0/lib/p5.js` とする。
- 初期プロジェクトは次の3ファイルを持つ。
  - `index.html`: p5.js CDN、`style.css`、`sketch.js`を参照する。
  - `style.css`: bodyとCanvasの基本表示だけを定義する。
  - `sketch.js`: `setup()`と`draw()`を持つ実行可能なサンプル。
- 追加ファイルは初回実装ではルート階層の `.js` のみとし、空文字、重複、予約名、パス区切り、危険な文字を拒否する。
- 追加したJavaScriptは、ユーザーが `index.html` に `<script src="追加ファイル.js"></script>` を追加した場合だけ実行する。暗黙の全ファイル実行は行わない。
- `srcdoc`生成には `DOMParser` と構造化DOM操作を使い、正規表現だけでHTML全体を組み替えない。
- ローカルの `<link href="style.css">` は `<style>` へ、ローカルの `<script src="*.js">` はインラインscriptへ置き換え、index.htmlに書かれた順序を維持する。
- リモートscriptはp5.jsのjsDelivr URLだけを許可する。未許可URLがある場合は実行せず、コード画面にエラーを表示する。
- iframeは `sandbox="allow-scripts"` のみを付け、`allow-same-origin`、popup、top navigation、form送信は許可しない。
- 生成するsrcdocへ制限的なCSPを挿入し、親画面のCookie、Storage、Firebase状態をユーザーコードへ公開しない。
- ユーザーコードの同期無限ループは同一タブのrendererへ影響する可能性がある。停止操作でiframeを破棄できるようにするが、完全な強制停止保証はできないため残存リスクとして扱う。
- CDNがオフラインの場合、編集内容は維持し、プレビュー側へp5.js読込失敗を表示する。

## Detailed Loops

### Loop 1: DESIGN.md更新

- Objective: 今回の配置、AIスレッド、スケッチ実行仕様を実装前にSSoTへ反映する。
- TDD test to add or change:
  - `tests/docs/designSsoT.test.ts` に2パネル均等配置、AI履歴、30ターン、スケッチ、sandbox実行の記述確認を追加する。
  - ヘッダーの4パネル名が `資料 / ホワイトボード / AIチャット / スケッチ` であることを確認する。
- Minimal implementation steps:
  - `DESIGN.md` の「図表・コード」をユーザー向けには「スケッチ」へ更新する。
  - 自由配置の右下リサイズと2パネル時の50% Gridを追記する。
  - AIチャット上部操作、履歴ダイアログ、30ターン上限、要約引き継ぎを追記する。
  - p5プロジェクト構造、バージョンタグ、sandbox付きプレビューを追記する。
- Unit test command to run after the task: `npm run test -- designSsoT`
- Refactoring checkpoint: component名や一時的なclass名をDESIGN.mdへ書かず、ユーザーが判断できる仕様に限定する。
- Completion criteria: 今回の名称、操作、状態遷移、安全境界をDESIGN.mdだけで判断できる。

  - 斜線は疑似要素または内側要素に限定し、`cursor: nwse-resize` と `touch-action: none` を設定する。

- Refactoring checkpoint: 確認用ログ、一時fixture、Secret値、手動fallbackを残さない。
- Completion criteria: 全テスト・Lint・buildが通り、秘密値漏洩がなく、本番確認の実施有無と結果が報告される。

## Verification Strategy

- 各Loopは `失敗テスト追加 -> 最小実装 -> 対象テスト成功 -> リファクタリング -> 対象テスト再実行` の順で進める。
- 自由配置のリサイズはcomponent eventと純粋なbounds計算を別テストにする。
- 2パネルGridはCSSの見た目だけに依存せず、visible count class、DOM順、実ブラウザ矩形を確認する。
- AI threadのturn数、status遷移、title、summary継承はDOMなしの純粋モデルで先に固定する。
- AIの永続化はInMemory repositoryでdomain契約、Firestore adapter testでpathとpayloadを確認する。
- AI履歴のユーザー分離は `uid + noteId + threadId` の3境界をテストし、別ユーザーのデータをfixtureへ含める。
- 30ターン上限と100回/日上限は別テストにし、要約が日次quotaを1回消費するケースを含める。
- OpenAI SDKはportのfakeでunit testし、通常のテストでは実API、実キー、ネットワークを必要としない。
- Functionsは未認証、入力不正、ノート不存在、quota超過の各段階でOpenAI portが未実行であることを確認する。
- quotaはFirestore transactionの競合を含めて検証し、クライアントから利用数を書き換えられないことをSecurity Rules testで確認する。
- APIキーが必要になるのはLoop 40以降の実通信確認だけとし、Loop 39でユーザーへローカル用と本番用の設定方法を案内する。
- 秘密値の入力はユーザー自身の端末またはFirebase CLIで行い、チャット、Git差分、ログ、スクリーンショットへ含めない。
- srcdoc生成は、HTML構造、実行順、CSP、未許可URL拒否を純粋関数で確認する。
- iframe componentはsandbox属性、message source、run ID、listener cleanupをjsdomで確認する。
- 実p5.js描画はunit testだけで完了扱いにせず、ヘッドレスChromeでCanvasの非blank pixelを確認する。
- レスポンシブ確認では `documentElement.scrollWidth === clientWidth`、全panel bounds、2パネル幅差を数値で取得する。

## Rollback / Follow-up Notes

- 表示名変更を戻す場合も内部ID `diagram-code` は維持するため、canonical titleとDESIGN.mdだけを差し戻せる。
- 2パネルGridに問題がある場合、count class生成を残したままcount-2 CSSだけを既存3カラム配置へ戻せる。
- AI thread UIに問題がある場合、repositoryデータは保持し、active threadを最新1件へ固定して履歴ダイアログだけを一時的に外せる。
- 要約処理に問題がある場合、30ターン上限を維持したままrollover操作を無効化し、元threadをread-only履歴として残す。
- Firestoreへ保存したthread/messageは削除せず、旧 `chatMessages` pathからの自動移行も今回行わない。実データが存在する場合は別の移行計画を作る。
- p5 runtimeに問題がある場合、編集projectを維持したままiframe実行だけを停止し、コード編集機能へ戻せる。
- OpenAI接続に問題がある場合、Callableの公開とFunctions client接続だけを外し、fixed clientを開発・テスト用途に限定して調査する。認証、履歴、quotaデータは削除しない。
- Secret更新時は `functions:secrets:set OPENAI_API_KEY` 後に参照Functionの再デプロイが必要になる。古いSecret versionの破棄は動作確認後に別操作として行う。
- rollbackやログ調査でもAPIキー値を表示せず、Secret Manager上の値をリポジトリへ書き戻さない。
- 将来のスケッチ永続化では `users/{uid}/notes/{noteId}/sketchProjects/{projectId}` を候補とし、HTML・CSS・JSのサイズ上限、Firestore分割、Security Rulesを別計画で設計する。
