## Goal / Scope

このループでは、Gauss Notebookのノート作成とノート詳細の中心体験を、MVPとして使える状態へ近づける。

- 新規作成したノートをFirestoreの `users/{uid}/notes/{noteId}` 配下へ保存し、ページ更新や再表示後も復元できるようにする。
- 「数学ノート一覧画面」は、作成フォーム常時表示と3分割検索を廃止し、1つの検索カードへ統合する。
- 一覧検索は「ノートタイトル」または「タグ」の部分一致を対象にする。教科検索欄は表示しない。
- 「ノートを作成」ボタンは検索カード右側へ残し、押下後にモーダルまたはドロワーでタイトル/タグ入力フォームを開く。教科入力はHOMEでも一覧画面でも不要とする。
- ノート詳細中央のホワイトボードは、通常時はMarkdown形式の記入エリアとし、`preview / md` の切り替えだけを提供する。
- 旧ホワイトボードのペン、テキスト、図形、数式、消しゴム、選択、手書き整形メニューは削除する。
- Markdownホワイトボードに手書き鉛筆ボタンを追加し、全画面Canvasで手書きして保存すると、Markdown本文内に画像として埋め込む。
- 埋め込まれた手書き画像には編集ボタンを持たせ、再編集できるようにする。

今回の非対象:

- 共有機能、共同編集、ノート公開、権限ロールの追加。
- AIによるMarkdown生成、手書きOCR、数式認識。
- 画像ファイルのStorage永続化の本格対応。Firestoreドキュメントサイズ上限に近い画像は後続でStorage移行する。
- Markdownエディタの高度なツールバー、WYSIWYG、複数カーソル。

現状確認:

- `src/features/notes/notesStore.ts` は `notes = ref([...initialMathNotes])` に対して `notes.value = [note, ...notes.value]` するだけで、Firestore保存を呼んでいない。
- `src/features/notes/firestoreNotesRepository.ts` には `list/get/save/remove` があるが、`Home.vue` と `NotesListView.vue` の作成処理から未接続。
- `src/views/NotesListView.vue` は `notes-view__create` と `notes-view__filters` が分かれており、検索欄は `キーワード / 教科 / タグ` の3つ。
- `src/features/notes/searchNotes.ts` は `keyword/subject/tag` を別条件として扱い、全角半角正規化はしていない。
- `src/components/whiteboard/WhiteboardPanel.vue` は `WhiteboardToolbar` と固定の数式サンプルを表示しており、Markdown本文や手書き画像ブロックの概念はまだない。
- `package.json` にはMarkdown renderer依存がないため、Markdownプレビューは軽量実装から始めるか、導入する場合は別ループで依存追加を明示する。

## Assumptions and Risks

- Firestore database IDは既存方針どおり `(default)` を前提にし、`getFirestore()` の通常接続を使う。
- Firestore保存先は既存の `noteDocumentPath` / `notesCollectionPath` を使い、パスの `uid` を権限の主軸にする。
- `ownerUid` は表示と整合性チェック用に残すが、認可判断はユーザー入力フィールドではなくFirestore pathとSecurity Rulesで固定する。
- 既存の `initialMathNotes` は開発用fixtureとして残すか、Firestore読込前のデモデータとして扱うかを実装時に決める必要がある。ログイン済みユーザーではFirestore読込結果を優先する。
- Firestore通信は非同期なので、作成中/保存失敗状態を持たないと、UI上は作成できたように見えて保存失敗するリスクがある。
- 一覧検索で教科検索を廃止すると、既存テストの `search-subject` 期待値を更新する必要がある。
- 全角半角差の吸収は `String.prototype.normalize("NFKC")` を基本にする。ただし日本語かなの表記揺れ、数学記号の完全同一視までは対象外にする。
- Markdown previewでHTMLを直接許可するとXSSリスクがある。MVPではHTMLタグをescapeし、見出し/リスト/コード/画像ブロックなど必要最小限から始める。
- 手書き画像をdata URLとしてFirestoreに保存すると、画像サイズ次第でドキュメント上限に近づく。初期実装では圧縮、サイズ上限、将来Storage化の境界を持つ。
- 全画面Canvasはモバイル/デスクトップでpointer座標がずれやすい。座標変換関数をテスト可能に切り出す。
- `DESIGN.md` のモノクロ、青アクセント、ニューモーフィズム、767px以下縦並びを一覧と手書き画面のCSSでも維持する。

## Detailed Loops

### Loop 1: 現状仕様テスト固定

- Objective: 新規作成ノートが現在はPiniaメモリ上にしか追加されない事実を、永続化改修前のテストで明確にする。
- TDD test to add or change: `tests/notes/notesStore.test.ts` に、`createNote` がrepositoryを呼ぶべきという失敗テストを追加する。
- Minimal implementation steps:
  - まずfake repositoryをspyできる形でテストに置く。
  - 現状では `save` が呼ばれないため失敗することを確認する。
  - まだ実装は変えず、次ループの設計入力にする。
- Unit test command to run after the task: `npm run test -- notesStore`
- Refactoring checkpoint: 現状確認用のテスト名を、最終仕様のテスト名へ自然に移行できる形にする。
- Completion criteria: Firestore永続化が未接続である問題がテストで再現できる。

## Rollback / Follow-up Notes

- Firestore永続化で問題が出た場合は、repository注入により `InMemoryNotesRepository` へ戻せるようにする。
- 手書き画像data URLが大きい場合は、後続でFirebase Storageへ保存し、Markdown内はStorage pathまたはdownload URL参照へ移行する。
- Markdown rendererを自前実装で始めた場合、要件が増えた時点で `markdown-it` 等の導入を別ループで判断する。
- Firestore Security Rulesは既存の `users/{uid}/...` 方針を守る。共有や公開リンクを入れる場合は別計画に分ける。
- 一覧画面の教科検索と、ノート作成時の教科入力はどちらも削除する。既存データの `subject` フィールドは互換性のため残す場合でも、新UIでは使わない。
