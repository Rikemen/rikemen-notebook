## Goal / Scope

ノート詳細画面の上部ナビゲーションを、ワークスペース内のパネル表示を管理する操作領域へ変更する。

- `WorkspaceHeader.vue` から「ノート一覧」「マイノート」「テンプレート」「AIアシスタント」「使い方」を削除する。
- 旧ナビゲーションの代わりに、次の4つのパネル表示ボタンを置く。
  - 教科書
  - ホワイトボード
  - AIチャット
  - 図表・コード
- 各ボタンは対象パネルの表示ON/OFFを切り替え、`aria-pressed` でも状態を通知する。
- パネル右上の `×` はデータ削除ではなく表示OFFとして扱う。
- 表示OFFになったパネルは、ヘッダーの対応ボタンから再表示できる。
- パネルを閉じて再表示しても、Markdown、手書き画像、AIチャット、コード、教材の選択状態などを失わない。
- パネルの移動、リサイズ、最小化、最大化、別タブ表示は維持する。
- パネルの表示状態とレイアウトはノート単位で管理する。
- デザインは `DESIGN.md` をSSoTとし、モノクロ、青アクセント、ニューモーフィズム、既存トークンを維持する。

今回の非対象:

- パネルそのものをユーザーが追加・複製する機能。
- パネル名や並び順をユーザーが編集する機能。
- 教材ファイル、手書き画像、チャット履歴、p5.jsプロジェクトのFirestore/Storageスキーマを新規設計すること。
- 既存の保存済みデータを削除する処理。
- HOMEなどノート詳細画面以外のグローバルヘッダー変更。

## Assumptions and Risks

- `DESIGN.md` 7.1は現在、ヘッダー中央に旧5ナビゲーションを置く仕様であり、今回の要件と競合する。実装前に `DESIGN.md` を更新し、以後のSSoTを4パネル表示ボタン仕様へ変更する。
- 表示状態は次のように定義する。
  - `normal` / `maximized`: 表示ON。
  - `minimized` / `closed`: メイン領域では表示OFF。
  - OFF状態のヘッダーボタンを押すと `normal` に復元する。
  - ON状態のヘッダーボタンを押すと `closed` にする。
- 最小化状態には既存の `MinimizedDock` からの復元導線も残す。ヘッダーから復元した場合も同じ `restorePanel` の状態遷移を使う。
- 最大化中のパネルをOFFにするときは、最大化前の `previousBounds` を保持して閉じる。再表示時は最大化前の位置とサイズへ戻し、いきなり最大化状態では開かない。
- `closePanel` はレイアウトの `state` だけを変え、ホワイトボードページやチャットメッセージなどのコンテンツ削除APIを呼ばない。
- 現在の `WhiteboardPanel.vue` と `DiagramCodePanel.vue` は編集データをコンポーネントローカルに保持しているため、`v-for` から外れると内容が失われる。ノートIDをキーにしたPinia stateまたは既存repositoryへ移す必要がある。
- `AiChatPanel.vue` のメッセージはPiniaにあるため再マウント後も残るが、入力途中の `prompt` はローカルstateなので消える。入力途中の文も保持対象にする。
- `TextbookPanel.vue` の教材選択とページ選択はローカルstateであり、現在は `noteId` を受け取っていない。ノート単位の選択状態へ移すため、`WorkspaceView.vue` から `noteId` を渡す。
- この計画でいう「履歴を残す」は、パネルのOFF/ONおよびノート画面内の再マウントで既存内容を失わないことを必須範囲とする。ブラウザ再起動後の長期保存は既存のFirestore/Storage保存境界を利用し、新しい永続化スキーマが必要な場合は別計画に分ける。
- `localWorkspaceLayoutStorage.ts` の保存値には閉じた状態も含まれる。レイアウト形式を変更する場合だけ `WORKSPACE_LAYOUT_VERSION` を更新し、単なる状態遷移追加では不要なリセットを行わない。
- 上部に4ボタンを置くと狭い画面で操作があふれる可能性がある。デスクトップでは横並び、狭い画面では折り返しまたはメニュー化し、ページ全体の横スクロールを発生させない。

- Objective: 今回のヘッダー変更を `DESIGN.md` の正式仕様として定義し、実装との食い違いを防ぐ。

- Minimal implementation steps:

## Verification Strategy

- 各Loopは、対象テストを先に失敗させ、最小実装、リファクタリング、対象テスト再実行の順で進める。
- 表示状態の単体検証は `panelLayout.test.ts`、store連携は `workspacePanels.test.ts`、UI契約は `WorkspaceHeader.test.ts`、画面結合は `WorkspaceView.test.ts` と `workspaceMockAcceptance.test.ts` に分ける。
- 最低限、次の状態遷移を自動テストする。

| Before      | Operation                   | After                     |
| ----------- | --------------------------- | ------------------------- |
| `normal`    | ヘッダーボタンでOFF         | `closed`                  |
| `closed`    | ヘッダーボタンでON          | `normal`                  |
| `minimized` | ヘッダーボタンでON          | `normal`                  |
| `maximized` | ヘッダーボタンでOFF、再度ON | 最大化前boundsの `normal` |

- 4パネルすべてについて、同じnote IDでは内容を復元し、別note IDには内容を混ぜない。
- パネルOFF操作でFirestore/Storage/repositoryのdelete処理が呼ばれないことを確認する。
- `localStorage` のレイアウト保存値が破損・旧バージョンの場合は、既存のsanitize処理で初期配置へ戻ることを維持する。
- 手動確認では、パネルをすべてOFFにしてもヘッダーの4ボタンが残り、そこから1枚ずつ戻せることを必須とする。
- UI確認はブラウザ倍率100%で行い、ヘッダーのボタン欠け、パネル重なり、横スクロール、コンソールエラーを確認する。

## Rollback / Follow-up Notes

- 問題が発生した場合は、ヘッダーUI接続だけを戻せるよう、状態遷移関数、store API、コンテンツstate外部化を独立した変更単位にする。
- 旧5ナビゲーションを戻す場合でも、パネルの非破壊復元APIとコンテンツstate外部化は独立して維持できる構造にする。
- ブラウザ再起動や別端末でもホワイトボード、AIチャット、p5.jsコード、教材選択を復元する要件は、ユーザー別Firestore/Storage repository、Security Rules、容量上限を含む別計画として扱う。
- 特に手書き画像のdata URLをFirestore documentへ直接保存するとサイズ上限へ到達しやすいため、長期保存時はStorage参照方式を優先する。
- `×` を将来「パネル構成から完全削除」に変更する場合は、確認ダイアログ、データ保持期間、復元方法を別仕様として定義する。今回の `×` は表示OFFであり、データ削除ではない。
